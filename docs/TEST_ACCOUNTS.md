**날짜 표기**: 이 문서의 `D` 는 **데이터가 만들어진 날**입니다. `D+7` 은 그 7일 뒤, `D-30` 은 30일 전이에요.

**ID 값**: 공간 · 신청 ID 는 서버 DB 가 정하므로 문서에 적지 않았습니다. 해당 계정으로 로그인한 뒤 목록 API 로 확인하세요.

### 로그인

```http
POST /api/v1/auth/login
Content-Type: application/json

{ "email": "provider1@demo.dasisiheung.com", "password": "demo1234!" }
```

```json
{
  "success": true,
  "data": {
    "tokenType": "Bearer",
    "accessToken": "eyJ...",
    "accessTokenExpiresIn": 1800,
    "refreshToken": "...",
    "refreshTokenExpiresIn": 1209600,
    "member": { "id": 1, "email": "provider1@demo.dasisiheung.com", "name": "김정왕", "role": "PROVIDER" }

```

이후 요청에는 `Authorization: Bearer {accessToken}` 헤더를 붙입니다. 액세스 토큰은 30분, 리프레시 토큰은 14일 유효합니다.

- user1 이 보낸 제안: **120,000원** ("이틀 연속이라 조금만 조정 부탁드려요.")

### 1:1 대화

**user4 오체험 ↔ provider3 이거북**, 공간은 거북섬 마리나 전망 공간

1. user4: "안녕하세요! 주말 이틀 팝업 가능할까요? 테이블 2개 반입하려고 해요."
2. provider3: "네 가능합니다. 신청서 보내 주시면 바로 확인할게요!"

이 대화는 user4 의 마리나 신청과 같은 공간 · 같은 이용자라서, **신청에서 대화 열기를 해도 이 대화가 열립니다.** 신청 응답의 `conversationId` 에도 이 대화 ID 가 들어 있습니다.

다른 신청(user1 → 갤러리, user3 → 공원 앞 상가 등)은 아직 대화가 없어 `conversationId` 가 `null` 입니다. 대화 생성을 테스트하기에 좋습니다.

## 7. 기능별 테스트 시나리오

| 테스트할 기능 | 로그인 계정 | 하는 법 |
| --- | --- | --- |
| 공간 검색 · 지도 | 아무 계정 (로그인 없이도 가능) | 공개 공간 5곳이 시흥 정왕 · 배곧 · 거북섬에 흩어져 있음 |
| 인원으로 검색 | 아무 계정 | `headcount=10` → 정왕역 상가(8명)만 빠짐 |
| 가격 협의 가능 공간만 | 아무 계정 | `negotiableOnly=true` → 정왕역 상가만 빠짐 |
| 공간 신청 | user1 ~ user4 | `D+1` ~ `D+180` 사이 날짜로 신청 (확정된 기간은 피하기) |
| 수용 인원 초과 오류 | user 계정 | 정왕역 상가에 운영 인원 9명으로 신청 → `400 HEADCOUNT_EXCEEDS_CAPACITY` |
| 가격 협의 불가 오류 | user 계정 | 정왕역 상가 신청서에 `offerAmount` 를 넣음 → `409 PRICE_NEGOTIATION_NOT_ALLOWED` |
| 받은 신청 · 승인 · 거절 | provider3 | 수제 캔들 팝업 신청을 승인 또는 거절 |
| 가격 제안 수락 · 역제안 | provider2 | 일러스트 굿즈 전시 신청의 120,000원 제안을 수락하거나 역제안 |
| 신청에서 채팅 열기 | provider2 | 어린이 업사이클링 클래스 신청에서 '채팅' → 새 대화가 생김 |
| 이미 있는 대화 이어가기 | provider3 또는 user4 | 수제 캔들 팝업 신청에서 '채팅' → 기존 대화가 열림 |
| 받은 후기 · 답글 대기 배지 | provider1, provider2 | `GET /api/v1/provider/reviews?replied=false` → 1개씩 |
| 후기 답글 작성 | provider1, provider2 | 답글 대기 후기에 답글 |
